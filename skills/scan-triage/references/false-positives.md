# 常见误报与无害核实方法

原则：先查版本、配置和补丁记录，再考虑主动验证。需要主动验证时，只用扫描器自带的检测插件或厂商提供的检测脚本，不用利用代码；生产和工控系统放到测试环境或维护窗口，由用户在授权范围内执行。

## 1. 只凭版本号或 Banner 判定的漏洞

现象：扫描器看到 `OpenSSH 7.4`、`Apache httpd 2.4.6` 这类版本号，就把该版本所有历史 CVE 都列出来。

为什么常是误报：RHEL/CentOS/Rocky/openEuler、麒麟、Debian/Ubuntu、统信等发行版会把安全补丁“向后移植”（backport）到旧版本号的软件包里，版本号不变，漏洞已修。Banner 也可能被改写或隐藏。

核实（在目标主机上由管理员执行）：

```bash
# rpm 系（RHEL/CentOS/Rocky/openEuler/麒麟服务器版等）
rpm -q openssh-server
rpm -q --changelog openssh-server | grep -i "CVE-2023-48795"

# deb 系（Debian/Ubuntu/统信等）
dpkg -l | grep openssh-server
zcat /usr/share/doc/openssh-server/changelog.Debian.gz | grep -i "CVE-2023-48795"
```

```powershell
# Windows：列出已装补丁，与微软安全公告（MSRC）里该漏洞对应的 KB 编号对照
Get-HotFix | Sort-Object InstalledOn
```

上面的 CVE 编号只是示例，换成报告里的编号。还应查发行版自己的安全公告或 CVE 跟踪页面，确认当前包版本是否已修复。

## 2. 未登录扫描给出的“可能存在”“潜在”

未登录（unauthenticated）扫描看不到补丁和配置，只能推测。核实办法：改用登录扫描复测，或由管理员直接检查对应配置项、补丁或软件包版本。

## 3. Nmap 的端口状态与服务识别

| 现象 | 含义 | 处理 |
|---|---|---|
| `open` | 有服务在监听并响应 | 按服务评估 |
| `closed` | 主机可达，但端口没有服务 | 一般无需处理 |
| `filtered` | 无响应或被 ICMP 拒绝，多为防火墙丢弃 | 不能当作开放，也不能当作安全 |
| `open\|filtered` | 无法区分开放与过滤，UDP 扫描常见 | 结合服务探测或主机侧检查确认 |
| `tcpwrapped` | 三次握手完成后服务立即断开 | 常见于 TCP Wrappers、访问控制、负载均衡或防护设备；服务未知 |
| 服务名带 `?`（普通输出），或 XML 里 `method="table"` | 服务名只是按端口号推测，没有探测确认 | 加 `-sV` 复测，或到主机上查监听进程 |
| 一台主机几百上千个端口全是 `open` | 防护设备、SYN 代理或蜜罐代答 | 抽查几个端口做版本探测，核对网络拓扑 |

到主机上确认监听进程：Linux 用 `ss -lntup`，Windows 用 `Get-NetTCPConnection -State Listen` 或 `netstat -ano`。

## 4. Web 扫描

- 软 404：目录爆破结果大量返回 200 且长度相同，多半是自定义错误页。按响应长度或内容过滤后再看。
- 基于时间的 SQL 注入：网络抖动或服务器负载会造成延迟误判。对比正常请求的响应时间基线，由授权人员人工复核。
- 反射型 XSS 出现在 `application/json` 等非 HTML 响应里：浏览器一般不会执行，通常不可利用。
- 版本泄露类（Server 头、错误页暴露版本）：本身是信息级问题，真正的风险取决于实际版本有没有漏洞。

## 5. SSL/TLS

- 弱协议、弱加密套件：确认是服务端真的支持，而不是扫描器推测。可由用户在授权范围内执行 `nmap --script ssl-enum-ciphers -p 443 <目标>` 或 testssl.sh 复核。
- 由负载均衡或 WAF 终结 TLS 时，要改的是这些设备的配置，不是后端服务器。
- 自签名、过期证书在内网很常见，按资产用途判断风险，不一概定为高危。

## 6. 中间设备与 NAT

扫描结果可能来自负载均衡、WAF、NAT 映射或代理，而不是你以为的那台主机。对照资产台账和网络拓扑，确认 IP 背后到底是什么设备。

## 7. 告警误报

- 单位自己的漏扫设备、运维主机、监控探针触发的告警，先核对源 IP 白名单。
- 业务的正常请求命中签名（例如参数里本来就有 SQL 关键字）。
- 判定“攻击成功”要有证据：响应码 200，且返回内容里有命令执行结果、敏感文件内容，或之后出现异常外联、新建账号、新进程等后续行为。只有请求命中规则，最多算攻击尝试。
